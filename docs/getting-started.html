4

Register the SPA in Entra ID

The public client — the thing users actually sign in through in the browser.

App registrations → New registration again, a second one:

entra.microsoft.com / App registrations / New registration
The platform choice (SPA vs Web) matters more than any other field on this form — see the warning below.
⚠️

Pick "Single-page application", not "Web." This is what makes the app a public PKCE client with no secret. Picking "Web" instead makes Entra expect a client secret, and sign-in fails with AADSTS9002326. This project deliberately has no secret anywhere.

FieldValue
Namesso-spa
PlatformSingle-page application (SPA)
Redirect URIhttp://localhost:3000 — or whatever port you plan to use, see step 6

From its Overview, copy the Application (client) ID → this becomes SPA_CLIENT_ID.

API permissions → Add a permission → My APIs → sso-resource-server → Delegated permissions → check Api.Access → Add permissions. Then Grant admin consent (or each user consents individually at first sign-in — also fine).

5

Assign the app role to yourself

The role exists now, but nobody holds it yet.

Entra ID → Enterprise applications → sso-resource-server → Users and groups → Add user/group → pick your own account → select Resource Admin → Assign.

ℹ️

Skip this and everything still works — /api/resource returns 200, but /api/admin correctly returns 403 (authenticated, not authorized). That's a real acceptance criterion, not a bug, so it's fine to test that path deliberately by not doing this step for a second account.

🔁

Role changes only appear in a newly issued token — sign out (or clear the tab's session storage) after assigning it.

Troubleshooting


    

      Redirect URI mismatch AADSTS50011
      

        
The redirect URI registered on the SPA app in Entra must match your running URL exactly,
        including the port. If you changed the SPA host port in step 6, go back to the SPA app registration's
        Authentication blade and update (or add) the matching redirect URI.

      

    


    

      Cross-origin token redemption AADSTS9002326
      

        
The SPA was registered under the Web platform instead of Single-page application.
        Go to the SPA app registration → Authentication → remove the Web platform entry, then
        Add a platform → Single-page application and re-add the redirect URI.

      

    


    

      MFA required AADSTS50076
      

        
Your tenant requires multi-factor authentication. This surfaces most often when scripting
        against the tenant (e.g. the Azure CLI); signing in through a normal browser tab handles MFA
        interactively without issue.

      

    


    

      Role-gated endpoint returns 403 even after assigning the role
      

        
Role assignment only affects newly issued tokens. Sign out of the app (or clear the
        tab's session storage) and sign back in to force Entra to mint a fresh token carrying the role.

      

    


    

      "insufficient privileges" when trying to register an app
      

        
Some tenants block non-admin users from creating app registrations. Ask a tenant admin to either
        enable Users can register applications (Entra ID → Users → User settings), or grant you the
        narrower Application Developer directory role — both unblock this without other changes.

      

    


    

      Port already in use
      

        
Something else on your machine is already listening on 3000 or 8080. Set
        SPA_HOST_PORT / API_HOST_PORT to unused ports
        in the builder above, regenerate .env, and update the SPA's redirect URI
        in the portal to match the new SPA port.

      

    


    

      docker compose up fails immediately with a missing-variable error
      

        
The compose file requires TENANT_ID, SPA_CLIENT_ID,
        API_CLIENT_ID, and API_SCOPE to be set — it refuses
        to start with placeholders left blank. Re-check your .env was saved in the
        repo root (same folder as docker-compose.yml), not somewhere else.
